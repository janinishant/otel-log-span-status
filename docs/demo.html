otel-log-span-status

Marks the active OpenTelemetry span as ERROR when an error-level log is emitted, so tail samplers keep the traces that matter. A YAML ignore list keeps expected errors from doing the same.

01  Why tail sampling

A busy service sends millions of traces a day.
Storing every one is expensive, and most are healthy requests no one will open.
A tail sampler waits for each trace to finish, then decides whether to keep it.
Its most important rule: keep any trace with a span marked ERROR.

Logs go to a separate backend.
The sampler never reads them.
One request fails. The error goes to the logs, but the trace still says UNSET.
To the sampler it looks healthy, so 99 times in 100 it is dropped.

The span comes from your existing OTel instrumentation.
install() adds one handler to the root logger.
An error log now sets the active span to ERROR.
So the tail sampler keeps the trace.

Not every error log means the request failed.
A record that matches any rule leaves the span alone.
Retries and noisy libraries don't force their traces to be kept.
No rule matches, so the span is marked ERROR.
Real failures keep their traces. Expected noise doesn't.
